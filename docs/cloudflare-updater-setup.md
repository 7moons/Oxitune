# Auto-updater over a private repo, via Cloudflare Worker

## Why this exists

The updater endpoint currently in `src-tauri/tauri.conf.json` is:

```
https://github.com/KayZedd/ytmd/releases/latest/download/latest.json
```

That URL only works for a **public** repo. While `KayZedd/ytmd` is private,
GitHub returns 404 for unauthenticated requests to release assets — so the
in-app updater can never see a release, no matter how many you publish.

The fix: a small Cloudflare Worker holds a GitHub token server-side and
re-exposes exactly two things publicly — the update manifest, and the
installer bytes — without ever exposing the token or the rest of the
private repo. `worker/` in this repo already has the full, ready-to-deploy
implementation (`worker/src/index.ts`, `worker/wrangler.toml`). This doc is
just the remaining steps to actually turn it on, since those need your own
Cloudflare/GitHub accounts and credentials.

**When the repo eventually goes public**, skip all of this: revert the
endpoint back to the plain GitHub URL above and the worker is no longer
needed (see "Reverting" at the bottom).

## What the worker does

- `GET /latest.json` — fetches the latest **published** release (drafts and
  prereleases are invisible to it, same as today), reads its `latest.json`
  asset (already generated by `release.yml` via `createUpdaterArtifacts:
  true`), rewrites each platform's `url` to point back at the worker's own
  `/download/...` route, and returns the patched JSON.
- `GET /download/:filename` — looks up that asset on the latest release and
  streams its real bytes back, using the GitHub token to fetch it.

Neither route requires the client (the Tauri updater) to know anything
about GitHub or hold any credential — it just talks to the worker like any
other HTTPS endpoint.

## Steps to actually turn it on

### 1. Create a GitHub token scoped to just this repo

GitHub → Settings → Developer settings → **Fine-grained personal access
tokens** → Generate new token:

- Repository access: **Only select repositories** → `KayZedd/ytmd`
- Permissions: **Contents** → Read-only (this alone covers releases and
  release assets). Leave everything else on "No access".
- Set an expiration you're comfortable rotating on (e.g. 1 year).

Copy the token once — you won't see it again.

### 2. Install wrangler and log in

```bash
cd worker
bun install          # pulls in wrangler + @cloudflare/workers-types
bunx wrangler login  # opens a browser to authorize against your Cloudflare account
```

### 3. Store the GitHub token as a Worker secret

```bash
bunx wrangler secret put GITHUB_TOKEN
# paste the token from step 1 when prompted — it is NOT written to any file in this repo
```

`worker/wrangler.toml` already sets `GITHUB_OWNER`/`GITHUB_REPO` as plain
vars (not secret — they're not sensitive). Update them there if the repo is
ever renamed or transferred.

### 4. Deploy

```bash
bunx wrangler deploy
```

Wrangler prints the worker's URL, e.g.:

```
https://ytmd-updates.<your-subdomain>.workers.dev
```

(Optional: attach a custom domain/route in the Cloudflare dashboard instead
of the default `workers.dev` one — purely cosmetic, doesn't change anything
below.)

### 5. Point the app's updater at the worker

Edit `src-tauri/tauri.conf.json`:

```jsonc
"plugins": {
  "updater": {
    "pubkey": "...", // unchanged
    "endpoints": [
      "https://ytmd-updates.kayzed.workers.dev/latest.json"
    ]
  }
}
```

Commit that change, rebuild (`bun run tauri build` or wait for the next
tagged release), and the running app will start checking the worker instead
of GitHub directly.

### 6. Cut a release and verify

1. Tag and push as usual (see `README.md` → "Releasing a New Version").
2. Once CI finishes, **publish** the draft release on GitHub (the worker's
   `/releases/latest` lookup ignores drafts, same as the raw GitHub
   endpoint always did).
3. Sanity-check the worker directly:
   ```bash
   curl -s https://ytmd-updates.<your-subdomain>.workers.dev/latest.json | jq .
   ```
   You should get back the same shape tauri-action's `latest.json` always
   had, except every `url` now points at
   `https://ytmd-updates.<your-subdomain>.workers.dev/download/...`.
4. Grab one of those download URLs and confirm it actually returns the
   installer bytes (`curl -I <url>` should show `200` and a real
   `content-length`, not a GitHub login redirect).
5. Launch a build on the *previous* version and confirm Settings → About &
   Updates finds the new one and installs it.

## Notes / trade-offs

- **This makes your compiled installers effectively public.** Anyone who
  guesses or is given the worker URL can download the binaries (not the
  source, not the repo) without a GitHub account. If that's not acceptable,
  add a shared-secret check in the worker (e.g. require a custom header and
  configure it via `tauri_plugin_updater::Builder::header(...)` in
  `src-tauri/src/lib.rs`) before shipping this — not implemented yet since
  you hadn't asked for it.
- **Rate limits**: each `/latest.json` hit costs 2 GitHub API calls, each
  `/download` hit costs 2 more. Authenticated GitHub API allows 5000/hour —
  plenty for personal-scale usage. If that ever matters, add Cloudflare's
  Cache API in front of `/latest.json` (the `Cache-Control: public,
  max-age=120` header is already there as a hint for exactly this).
- **Token rotation**: if the fine-grained PAT expires or is revoked, the
  worker starts returning 500s from `getLatestRelease` — regenerate a new
  token and `wrangler secret put GITHUB_TOKEN` again, no redeploy needed.

## Reverting once the repo is public

1. `src-tauri/tauri.conf.json` → set the endpoint back to
   `https://github.com/KayZedd/ytmd/releases/latest/download/latest.json`.
2. `bunx wrangler delete` inside `worker/` (optional — or just leave it
   running unused, it costs nothing idle).
3. Revoke the fine-grained PAT from step 1, since nothing needs it anymore.
